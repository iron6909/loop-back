## I1：外部源核对与 Kokoro 公开分发

- [ ] 完成研究笔记核对清单 1–3、5：回访 kokoro/vits 文档页；用 GitHub API 枚举 `tts-models` 发布资产（`kokoro-en-v0_19.tar.bz2`、`kokoro-int8-en-v0_19.tar.bz2`、`vits-piper-*.tar.bz2` ×9、`espeak-ng-data.tar.bz2`）；获取 HF 仓库文件清单与可用 commit。
- [ ] 公开上游与 hf-mirror 双源独立下载，计算逐文件 SHA-256 与字节数（HF API 的 `lfs.sha256` 是 LFS OID，不能当作内容摘要）。
- [ ] 下载现有 CDN 归档，解包后与公开源**逐文件**比对（含 espeak-ng-data 目录树；不能比对整包摘要，gzip 重打包必然改变整包字节）。Kokoro int8 按方案决策树定身份：与官方资产逐字节一致则直接引用公开源；不一致或无公开 int8 则如实记录差异并另行决策。
- [ ] 建立 TTS 公开资源目录：repository + revision/tag + layout + license + 逐文件 SHA-256/字节数 + dependencies=[espeak-ng-data]；复用或泛化 ASR 公开资源目录抽象，不为测试引入新的生产门面。
- [ ] Kokoro 管理器切换公开源 URL 构造；逐文件（或整包）下载、staging 校验、原子发布、失败回滚、`.part` 续传与取消语义保持不变。
- [ ] 旧归档安装清单继续识别；损坏/截断安装回到未安装态并给出修复入口；共享发音数据缺失只补该依赖，不重下模型本体。
- [ ] 移除 Kokoro 路径对 `modelCdnUri` 的依赖；词典等仍使用的共享路由保留。

验收/回归：有效旧安装不重下、错误摘要/中断/取消/发布失败仍保留旧安装、镜像身份一致、损坏修复、只补共享依赖。重点文件：`test/services/tts/kokoro_model_manager_test.dart` 及既有安装测试。
