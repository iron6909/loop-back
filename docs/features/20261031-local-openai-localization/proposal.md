# Echo Loop 本地 OpenAI 兼容服务改造提案

## 问题与范围

用户希望改造 `D:\Workspace\Github\Echo-Loop`：把现有云端 AI 改为可配置的本地 LLM，使用 OpenAI 兼容接口，并将调用远程接口的部分全部改造为本地功能。

用户已经确定了“本地 LLM + OpenAI 兼容接口”的方向。本提案比较的是接入位置与云端依赖的替代方式，不重新比较是否继续使用云端 AI。

“本地”暂按应用连接本机或用户局域网中的推理服务理解；LLM 的安装、模型下载和进程启动由用户管理，不默认把推理运行时嵌入 Flutter。手机访问电脑上的服务属于局域网部署，手机上的 `localhost` 仍指手机自身。

“全部远程接口”存在两个需要明确的产品边界：

- **AI 与运行依赖全部本地化**：AI、账号门控、配额、远程配置、统计和官方后端不再是学习的前提；是否保留用户主动使用的播客、直链、网盘和网页词典另行选择。
- **整个应用禁止公网访问**：上述能力之外，还要移除或停止一切公网内容获取、更新检查、资源下载、网页词典和外链打开。只使用本地文件、本地资源与指定局域网服务。

本提案覆盖两种边界涉及的全部已识别模块，推荐以“完整本地学习闭环，不依赖官方云端，不自动回退云端”为共同目标。严格禁止公网尚未由用户明确选择；播客、网盘等不能被默认为已获准删除，也不能在承诺“全部本地化”时悄悄保留公网调用。

当前只交付设计提案，不写产品代码、不启动模型、不运行实验、不修改原有任务清单或规划。是否扩大 Windows 原生能力、是否保留多语言转录、是否必须保留结构化结果逐字段渐显，均在下文单列，不能作为隐含缩减项。

### 已观察到的仓库事实

基于提交 `5574fe21a676184ada4f562f684e312b250998e4`，应用版本 `1.0.44`，Dart SDK 约束 `^3.9.2`。

1. 项目是 Flutter / Riverpod / Drift 应用，学习数据主要保存在本地。现成依赖包括 Dio（锁定 `5.9.2`）、`sherpa_onnx`（`1.13.4`）、`flutter_secure_storage`（`10.0.0`）、SharedPreferences、FFmpeg 和 `archive`。直接连接模型服务不需要先增加 OpenAI SDK。
2. `lib/services/sentence_ai_api_client.dart` 提供翻译、解析、单词词典、短语词典、意群切分和复述评估；`lib/features/chatbot/services/chat_api_client.dart` 提供学习助手。它们访问项目自有后端，使用自定义 NDJSON，而非 OpenAI Chat Completions 协议。
3. 结构化 NDJSON 由 `ops` 路径增量和显式完成帧组成；聊天使用文本增量和完成帧。现有缓存与控制器依赖 `isFinal`，因此只替换域名不能保持行为。
4. AI 调用前同时存在客户端登录检查、订阅/配额检查、Supabase Token Gate，以及运行时区域路由。直接把当前 Dio 的地址改成本地模型地址，仍可能被 Token Gate 阻断或被区域路由重写。
5. 云端字幕流程是申请 R2 上传地址、上传文件、提交任务、轮询并取回字幕；这不是 `/audio/transcriptions`。复述评估也上传录音，由后端先转录再评估，普通文本聊天接口不能直接替代。
6. 已有 `LocalTranscriptionTaskManager` 和 `OfflineAsrEngine.transcribeSegments`，可本机转录并写入既有 SRT / 字幕数据链路；已有本地词典及 Piper / Kokoro TTS，可复用。
7. 当前 ASR 模型目录只有 Whisper `tiny.en` / `base.en` / `small.en`，本地字幕来源固定为英语；原云端流程允许 `en` / `multi`。仅复用现有离线实现不能声称保留多语言能力。
8. `speech_practice_platform.dart` 的录音桥接目前只支持 iOS / macOS / Android；README 也将桌面正式发布列为未完成。Windows 上运行 LLM 服务，不等于 Windows 客户端的录音、FFmpeg 与全部插件已经可用。

## 候选方案

### A. Flutter 直接连接本地 OpenAI 兼容服务（推荐）

**机制**：应用保存一个用户提供的 `baseUrl`、`model` 和可选 `apiKey`，使用已有 Dio 调用 Chat Completions。客户端持有各学习功能的提示词与结果适配。语音优先复用当前离线 ASR、TTS 和字幕写库流程，不新增业务服务器。

**与现有代码的结合**：保留 Riverpod 状态与领域结果；在 AI client / controller 边界替换传输与鉴权，复用取消、generation 守卫、缓存和现有渲染。聊天已有 `ChatApi` 可替换实现，不先建设通用多供应商插件框架。

**结构化输出的最小版本**：聊天继续流式；解析、词典、意群、复述评估先请求完整 JSON，完成格式和语义校验后输出一个 `isFinal=true` 领域帧。翻译也可先完整返回。现有 provider 测试夹具已经使用单个 final 帧，因此此接口形状有代码依据；这只证明适配位置合理，不证明全部真实界面或目标模型已验收。相比当前逐字段渐显，结构化结果等待时间会更明显，需由用户接受这一展示差异。若必须保留逐字段渐显，应重新比较成本。

**收益**：少维护一个进程；直接符合用户配置本地 LLM 的目标；不再复制官方账户、计费、上传和轮询体系。现成网络、存储、ASR、TTS 依赖足够支撑基本接入。

**成本与失败模式**：客户端要补原来由后端承担的提示词、最终结果校验和 OpenAI SSE 解析；小模型可能产生错误 JSON、空内容、错误意群或不可靠讲解。推理冷启动、上下文窗口和移动设备 ASR 开销需要按实际硬件处理。OpenAI 兼容不代表支持相同 JSON Schema、工具调用或音频端点。

**可逆性**：领域模型、字幕存储和学习主流程仍沿原有边界；有证据需要时可把请求编排迁往网关。当前不为潜在迁移保留云端/本地双实现切换系统。

### B. 本地兼容网关承接原业务协议

**机制**：新增一个本地或局域网网关，对 Flutter 暴露原 `/api/v1/stream/*` 风格的 NDJSON，在网关内调用用户本地 OpenAI 服务、执行结构化验证，并可运行本地 ASR。

**适用收益**：若多客户端需要共享提示词、同一台电脑统一承担 ASR，或必须保留逐字段渐显，网关有集中的处理位置。客户端可较多保留流式协议消费代码。

**实际成本**：仍须解除 Flutter 中请求前的登录和额度门控，并处理统计、区域路由等，不能靠网关假造登录解决。网关还要承担部署、升级、端口、访问控制、取消、流式错误和音频生命周期。原网关协议、提示词及全部后端实现不在本仓库中，不能假定可直接复制。

**失败模式与可逆性**：新增进程成为运行前提；客户端取消不一定能停止后端推理；网关也无法让不支持结构化输出的模型自动可靠。它可保留客户端协议形状，但移除网关时仍需将编排迁回客户端。

**当前排名**：第二。只有目标硬件需要集中语音处理，或保留原流式表现具有明确价值时，额外服务才有足够收益。

### 已排除的捷径

- **只设置 `API_BASE_URL`**：路径、NDJSON、鉴权、区域回退和音频流程都不匹配，不构成完整替代。
- **把一切请求转到 `/chat/completions`**：登录、支付、RSS、音频识别、资源下载不属于文本生成，无法保持原功能。
- **仅隐藏付费按钮**：底层 Token Gate、配额检查、订阅刷新和原生统计仍会运行。
- **首版内置 LLM 运行时、自动下载大模型或新增多模型编排平台**：用户要求的是配置已有 OpenAI 兼容服务，目前没有足够需求支持这些新增机制。

## 推荐方案

暂推荐 **A：客户端直连本地 OpenAI 兼容服务 + 复用已有离线能力**。以下是待确认的设计方向，不是已经批准的接口合同。

### 配置与请求

- 提供一个本地 AI 设置入口：Base URL、模型名、可选 API Key、连接验证。模型名允许手动填写，不以 `/models` 可用作为前提；验证应实际执行一次最小推理请求。
- Base URL 明确定义为 API 根路径，例如 `http://127.0.0.1:1234/v1`。路径拼接保留用户指定的子路径，避免丢失 `/v1` 或拼出重复版本路径；拒绝非法 URI、内嵌账号密码等歧义输入。
- 用独立的 Dio 连接模型服务，不携带 Supabase token、官方平台/渠道头或权益拦截器，不经官方区域路由。没有 API Key 时不发送伪造 Bearer token；有 Key 时使用现成安全存储，不写入日志、云同步或明文备份。
- 先依赖基本 Chat Completions，不默认需要 Responses API、工具调用、严格 JSON Schema 或语音能力；是否使用 `response_format` 按选定服务的实际支持决定。
- 保留超时与输出长度等必要调节项，考虑模型冷启动和低性能设备；不能照搬云端固定等待上限后宣称本地服务不可用。LLM、ASR 并发受控，避免手机同时加载多个重模型。
- 对本地服务的 401 显示 Key/服务鉴权问题，对 404 显示地址/模型问题，对 429、超时和服务异常给出对应错误；不再引导官方登录或会员升级。失败不自动发送到云端，也不静默更换模型。
- 明确允许的回环/局域网服务边界；服务地址校验、重定向与 Key 转发不得绕开该边界。保留正常 TLS 校验，不为本地证书关闭所有证书检查。
- 分别处理 Android 发布包的 HTTP 明文连接、Apple 平台局域网权限和桌面沙箱网络权限；以当前 Flutter 网络栈和目标系统实测为准，不因 debug 包可连就认定 release 可用。局域网服务监听地址、手机到电脑的可达性与电脑防火墙也属于部署前提。

### 结果、流与缓存

- 每项功能使用简短的系统指令、目标语言、必要上下文和明确输出结构。学习原文、用户引用、转写都是待分析的数据，不作为执行指令。原后端提示词未出现在当前客户端中，需依据领域模型重建，效果不可默认为与云端一致。
- 句子解析保持 `grammar` / `vocabulary` / `listening`；单词保持 `headword`、音标、释义、搭配等字段；短语保持 `originalExpression`、`keyPoints` 等独立结构；意群保持 `medium` / `fine`；复述保留 `transcript`、`keyPoints`、`corrections`、`summary`、`rating`、`suggestion`。
- 最终响应必须先做结构、枚举、长度和必要语义校验。已有 `fromJson` 为展示流式半成品会容忍缺字段，不能把“能反序列化”当作“完整有效”。空对象、截断 JSON、漏词意群和不完整评级均不得缓存为成功。
- 聊天 SSE 使用 UTF-8 和事件边界解码；处理分包、多字节字符、空帧、结束标记、截断与错误。只有按实际服务协议确认正常完成才标为成功，网络 EOF 不能自动冒充 final；用户停止保留已有可见文本的既有语义。
- 复用现有“完整成功才入缓存”的规则。缓存身份加入服务地址、模型名、提示词版本、功能、目标语言及原有文本/上下文；Key 不进入缓存身份。旧云端缓存与新配置隔离，保留学习数据及原缓存，不全库清空。
- 保存新配置时作废旧配置的在途请求和聊天上下文，避免旧模型输出写入新缓存或覆盖新会话；取消、失败和重试沿用现有 generation / session 防竞态原则。

### 语音与资源

- 英语字幕先复用 `LocalTranscriptionTaskManager` 的转码、分段、SRT、合成词级时间戳和写库主干。合成词级时间戳与云端真实词级对齐并不等价，需在后续合同明确精度预期。
- 复述评估优先读取当前录音已有且对应同一 attempt 的有效本地转写；否则将录音转为 16 kHz 单声道 PCM WAV，再经独立 ASR 引擎分段转录，最后把原文和转写交给 LLM。空/失败转写不进入评估，不把 ASR 错误伪装成用户语言错误的确定证据。
- 现有评分路径 `transcribe()` 会使用 Silero VAD，仓库仍记录部分 Android 机型的 native 崩溃。分段字幕路径 `transcribeSegments()` 已不运行 VAD 推理；但 worker 初始化仍可根据配置创建 VAD，因此复述的独立转录配置应明确不传 VAD 路径。不能把避开一个崩溃面写成所有机型稳定的证明。
- 不直接复用当前为云端上传准备 AAC / 2 MB 上限的复述音频合同；改为本地转码与资源约束。原录音不被覆盖，临时文件、引擎和取消生命周期仍需完整处理。
- 多语言要求若保留，需要另外确认可用的多语言离线模型或本地 ASR 服务。Chat Completions 服务不一定实现 `/audio/transcriptions`；ASR 的能力、地址与时间戳格式不能凭 LLM 地址推断。未决前不删除原功能语义，也不宣称英语模型已覆盖 `multi`。
- 本地语音和词典资源目前多经官方 CDN 安装。严格本地运行须补文件导入或局域网资源源，复用现有归档校验和原子安装，不能要求用户手工放目录、跳过完整性验证或在缺模型时自动回公网下载。
- 严格本地边界下采用已就绪的离线 ASR / TTS；模型缺失应明确告知并指向本地资源导入。现有系统语音入口和自动降级行为不能未经确认保留。

### 全应用运行边界

若用户选择整个应用禁止公网：启动、回前台、后台、定时刷新、WebView、外部浏览器和原生 SDK 都需遵循这一边界。已有远程资料保留元数据及已下载文件，但不自动请求缺失封面/字幕，不续传公网下载；用户改用本地文件与资料包。远程问卷/偏好停止同步，本地备份与恢复保留。

若用户选择保留主动联网内容：需明确列出播客、直链、网盘、网页词典、资源获取或更新检查中的保留项，并相应更正“全部本地化”的描述。两种边界都不能让本地 AI 的失败触发官方云端回退。

当前不建议同时建设两个发行模式和任意网络策略引擎；先确定一个交付边界，用现有初始化和 provider 边界移除不需要的调用。严格本地模式的效果仍须由实施后的实际流量证据证明。

## 选择状态

- **用户已选方向**：本地 LLM，OpenAI 兼容接口；迁移全部远程调用。
- **尚未选择**：客户端直连 A 或本地网关 B；当前仅推荐 A。
- **待明确的决定条件**：主要客户端平台及设备、模型服务运行位置、服务/模型/版本；“全部远程调用”是否包含播客等用户主动联网内容；多语言转录和结构化逐字段渐显是否必须保留。
- 保存与提交本提案不代表批准实现、批准删除联网功能，或认定兼容性和性能已验证。

## 可行性问题

### 优先的有界证据问题：目标模型能否完成现有结构化学习任务

**候选**：A 的基本 Chat Completions + 完整 JSON 返回；B 同样受模型能力约束，不能靠增加网关绕过模型质量问题。

**依赖决策**：是否能采用最少客户端改动直接接入，是否需改提示词/模型，或确有理由引入集中结果处理。

**待补输入**：服务名称和版本、模型和量化版本、实际上下文上限、推理机 CPU / GPU / RAM / VRAM、客户端平台、回环或局域网部署。当前未提供这些信息。

**建议后续 spike 的边界**：只针对指定环境，用脱敏固定样例覆盖带上下文翻译、句子解析、单词、短语、意群、聊天和复述结构。检查实际返回形状、有效 JSON、非空必要内容、意群内容守恒、复述枚举与纠错依据；记录首响应/总耗时及资源占用。聊天检查完成与取消形状。连接成功或返回一句问候不能证明业务兼容。

**决定标准**：选定服务能在明确的运行环境和用户认可的等待预算内完成各必要任务；所有接受的最终对象通过结构及语义校验，错误对象明确失败、不缓存。若只能满足部分功能，结果为范围受限或未解决，不能宣布整体可行；先调整候选或与用户明确范围。延迟预算与样例数量在获得目标设备和使用方式后设定，不凭空指定统一性能门槛。

这里没有执行该实验，也没有认定目标服务支持 JSON 模式、SSE 的所有变体或音频端点。有可适用的现成证据时直接复用，不要求重复实验。

### 其他未知与普通实施验证的区别

- **会改变方案的未知**：若客户端是当前不支持录音的 Windows，或手机无法承担目标 ASR/多语言模型，需比较补原生能力与把 ASR 放在局域网电脑；这可能提高 B 的价值。不能默认只做 Android 来避开问题。
- **会改变范围的产品决定**：禁公网还是保留主动联网内容、多语言是否保留、结构化结果是否必须渐显。它们需要用户意图，不需要用实验替用户作决定。
- **已有支持但有限**：ADR-8/9 支持复用统一 TTS；ADR-10 与当前代码支持复用本地分段转录、字幕存储和取消边界。归档中报告的 macOS 短音频结果仅适用于当时模型与环境，不构成当前移动设备、长音频或 Windows 证据。
- **后续普通验证**：端点路径及 Key 处理、缓存配置切换、取消后旧回调、断流/错误 JSON、静音及长音频、原录音保留、备份不含凭证、网络访问覆盖与本地资源安装。现有 `test/services/sentence_ai_api_client_test.dart`、`test/providers/sentence_ai_provider_test.dart`、`test/providers/retell_review_evaluation_provider_test.dart`、本地转录/ASR/词典/聊天相关测试可沿用；本轮没有执行这些验收检查。

下一步先补齐上述部署与范围信息。若存在影响选择的兼容性未知，建议使用 `spike` 取得有界证据后更新同一提案，再确认 A/B；若已有适用证据，直接确认选择并交由 `spec` 完整化合同，不强制增加实验。
