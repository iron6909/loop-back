# 用持久授权的 tree URI 记住上次导入的文件夹

2026-11-12，实施「从文件夹导入合集」交互改版时确认：在本地偏好里记住一次成功导入的 SAF tree URI（含显示名），下次「从文件夹导入」先给一键入口，而不是再次从系统根目录逐级点进去。

Android 的目录选择器是 `ACTION_OPEN_DOCUMENT_TREE`。它不接受调用方指定初始位置，也无法按 MIME 过滤文件夹——应用既不能让选择器落在上次的目录，也不能在选择阶段灰掉「没有可导入音频」的文件夹。用户因此每次都要重走一遍文件树，这是「从文件夹导入」最直接的体验缺口。

可选方案有三种：

1. 只记住文件夹名，仍然走系统选择器：零原生改动，但解决不了重走文件树，只是在菜单里多显示一行名字。
2. 自建文件夹浏览器：能完全控制过滤与默认位置，但要在 Android 上重新实现一套存储访问 UI，并与 SAF 授权、第三方 DocumentsProvider 兼容性纠缠，代价远超收益。
3. 记住已持久授权的 tree URI，再用它重新列出子项（本决策）。

选择 3：原生在选择时本就调用了 `takePersistableUriPermission`，授权跨重启有效，只是此前没有把 URI 回传给 Dart。补一个回传字段与一个 `listDirectory(uri)` 通道方法即可复用同一套枚举逻辑，不需要新 UI 层。

约束与后果：

- 只记住一条（最近一次成功导入），不维护历史列表；文件夹被删除、移动或授权被撤销时，重新列出会失败，此时静默清空记忆并退回系统选择器，不弹错误。
- 记忆只在合集真正建成后写入；空目录、全跳过或不支持的格式不会覆盖已有记忆。
- 选择阶段的格式门禁只能放在「选完之后」：不合格文件夹原地拒绝并给出重选入口，不创建合集、不进入空列表。
- 文件夹的显示名由 provider 给出，仅用于界面；路径不做解析与展示（第三方 provider 的 document id 形态不可假定）。
- 目录导入只在 Android 提供，其他平台不展示入口（见 `directoryImportSupportedProvider`）。
